# 全力模式：完整文档与独立审核

用户要求全力模式、完整文档体系或并行深度分析时使用。遵守已限定范围，不自动扩大任务。
维护同时读 [maintenance-workflow.md](maintenance-workflow.md)。

## 产出与质量

按实际需求产出系统架构、核心模块、Guide 和索引，路径沿用 SKILL.md。
按源码和读者任务决定深度，不设最低章节、token、图表或调用次数。
`templates/fullpower/` 是深度组件和假设示例；只复用结构，不把示例机制、数字、事故和 API 当作项目事实。
复杂主题可分 Summary/Detail/Deep Dive，简单章节不强填。

## 阶段 0：项目探测

识别技术栈、构建入口、模块边界、测试和配置；列出文档、范围和未知，说明本轮实际范围。

## 阶段 1：分析

环境支持且请求授权并行工作时，将独立范围交给分析 agent；否则说明限制并串行完成可执行范围，不伪造调用。

| 角色 | 任务 | 返回内容 |
|---|---|---|
| 源码 | 接口、状态、算法、错误路径、调用关系 | 已读文件、API/状态表、关键分支、来源与未知 |
| 测试/配置 | 覆盖、配置约束、加载顺序 | 测试矩阵、未覆盖路径、默认值/单位/不当值后果及来源 |
| 系统 | 依赖、数据流、线程/事件模型 | 依赖边类型、端到端路径、外部依赖版本、核对范围 |

发现区分事实/推断/未知。算法、计数、枚举、方向性结论写入前由主 agent 回源码亲验。
使用实际可用工具，不执行硬编码私有桥接命令或假装存在 Task 工具。

## 阶段 2：补充研究

按未解决问题补读调用点、测试、配置和设计记录。外部参考只用于结构与表达，不为项目事实背书。
无需为了数量强制外部研究或采纳章节建议。

## 阶段 3：生成

遵循 [authoring-workflow.md](authoring-workflow.md) 与 [writing-quality.md](writing-quality.md)。
关键结论回看源码上下文；已核对来源可复用，不要求无意义重复读取。
公开 API 的行为、条件、结果和错误路径完整；示例注明运行状态；跨文档共用术语映射。

## 阶段 4：独立审核

审核 agent 不参与生成。提供文档、真实源码和明确范围，要求主动核验。

```text
核对文档与源码快照，范围为 <files/modules>。
报告文档位置、源码依据、严重度和具体修订建议。
区分实际运行、静态核对、未确认项。
检查准确性、完整性、深度、可操作性、结构及视觉。
重点核对 API/字段类型、分支方向、配置单位/默认值、并发约束、
错误路径、语义改写、事实/推断、术语及图文一致性。
不能因总分高而忽略阻断项。
```

可用 6 维各 0–10 分，但通过需同时满足总分 ≥50/60、语义阻断项为零、适用机械门禁通过。
严重事实错误、错误 API、关键条件遗漏、未经证实的危险操作均阻断通过。
无独立审核能力时注明未完成，不能声称全部全力模式验收完成。

## 阶段 5：修订

按严重度修订，再审修改结论及关联复述。最多 5 轮，连续两轮无改善时报告未解决项。
达到上限不表示通过；不设最低轮数或调用次数。

## 阶段 6：交付

执行 HTML 校验、语言检查、存量基线比较及代表页视觉/交互验证。
交付索引、源码快照、已覆盖/未覆盖范围、实际检查结果及遗留项，不用消耗量替代质量。
