目标：保留 module/system/guide、batch/maintain、HTML 模板和转换器，增加可追踪的语言质量检查，并统一生成与维护的验收规则。基于 main 的 c9ebc5c；实现及验证完成后推送 origin/2.0，不合并 main。

## 实施决策

- SKILL.md 只放触发、路由、共享契约和交付入口；详细编排按需加载。
- 语言模式按段落用途选择：strict 用于步骤/API 契约/排障；explain 用于架构叙述。CLI 的模式作用于本次输入，混合文档可分文件或对章节单独检查。
- 中文句长及英文词数只作提示，不能通过删除条件、例外或不确定性来达标。
- 只把显式禁用术语及未替换占位符当作语言错误；长句、宣传用语、模糊指代等作提示；机器不证明事实、术语语义等价或 STE 标准合规。
- 同一套工具先后生成 JSON 基线，按问题身份及出现次数比较；比较必须具有相同工具、目标集合和检查配置。默认阻断新 error；strict 同时阻断新 warning。
- 事实错误、错误 API、关键条件遗漏为语义阻断项，综合分数不能抵消。停在迭代上限时报告未通过，而非宣告达标。
- 不改现有视觉模板或转换器；1.x 自文档保留为有版本说明的历史快照。2.0 使用说明写入 README 与 references。

## 验证矩阵

1. 中文/英文、strict/explain、合法短文本与真实违规。
2. Markdown 围栏（不同长度）、行内代码、链接、HTML pre/code/script/style/SVG/Mermaid、CRLF：保持位置并避免误报。
3. 术语边界、合法别名、禁用别名、非法配置、代码标识：只处理明确定义的可检查情况。
4. “可能/may/might/could”、条件、否定及例外：不自动改写或删减。
5. 同名文件不同目录；问题换行但内容不变；旧问题减少而新问题出现；重复问题次数增长；目标或配置不一致。
6. HTML legacy 校验、--fix、--strict、--json、缺失文件与存量 --all；默认检查结果与开发前对照。

## 后续迭代（不包含在本次承诺）

- 用真实业务仓库评估语言提示的准确率与阅读效果，再决定哪些提示可提升为阻断项。
- 可选的源码引用存在性/行号验证、证据清单自动提取、API 示例实际运行；均应明确证据等级。
- 若扩展为完整 Markdown/HTML 解析器，重新评估依赖与离线安装成本。
