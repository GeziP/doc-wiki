3. 分层架构

系统按职责分为 4 个层级，上层依赖下层，禁止反向依赖：

Interface Layer CLI + Web UI + REST API
Application Layer 业务编排：RecipeManager, SequenceEngine
Domain Layer TaskScheduler, DeviceDriver, DataCollector
Infrastructure Layer Modbus, SQLite, FileSystem, Logger

设计决策 DeviceDriver 独立于 Application 层，直接属于 Domain。这样做是因为设备通信协议（Modbus） 的时序约束需要直接访问底层 Timer，经过 Application 层的间接调用会引入不可接受的延迟（>5ms）。

4. 核心模块职责

4.1 RecipeManager

职责：管理配方（Recipe）的加载、校验和版本切换。

维度说明
路径src/recipe/
核心 APIloadRecipe(), validateRecipe(), switchVersion()
依赖FileSystem（配方文件读取）, Logger
被依赖CLI, REST API, SequenceEngine
故障模式配方文件损坏 → 回退到上一个有效版本

4.2 TaskScheduler

职责：基于优先级的任务调度，支持依赖关系和取消传播。

维度说明
路径src/scheduler/
核心 APIschedule(), cancel(), getState()
依赖ThreadPool, PriorityQueue
被依赖SequenceEngine
故障模式队列满 → 拒绝新任务并返回 QueueFullError

详细设计见 TaskScheduler 模块设计文档。

注意 RecipeManager 和 TaskScheduler 之间不存在直接依赖。SequenceEngine 负责将 Recipe 转换为 Task 序列后再交给 Scheduler。如果发现二者直接交互的代码，属于架构违规。
Sources: recipe_manager.h:1-50 task_scheduler.h:1-60
