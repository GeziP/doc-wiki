1. 概述

1.1 背景

系统需要协调多个异步任务的执行顺序，确保高优先级任务优先调度，同时避免低优先级任务饥饿。 TaskScheduler 提供基于优先级的抢占式调度，支持任务依赖关系和取消传播。

1.2 解决方案

采用多级反馈队列（MLFQ）算法，将任务分为 4 个优先级层，每层独立管理。 调度器从最高优先级层开始扫描，空层跳过。层内使用时间片轮转，防止饥饿。

设计决策 选择 MLFQ 而非简单的优先级队列，因为生产环境中观察到低优先级清理任务 长期得不到执行，导致内存泄漏。MLFQ 的时间片机制保证每层在 500ms 内至少被调度一次。
Sources: task_scheduler.h:25-42 priority_queue.h:10-30

4. 核心概念

4.1 优先级定义

任务优先级由枚举 TaskPriority 定义， 位于 task_scheduler.h:30-35。 数值越小优先级越高：

枚举值数值用途时间片
CRITICAL0安全相关、紧急停机无限制（立即执行）
HIGH1实时控制循环100ms
NORMAL2常规业务逻辑50ms
LOW3后台清理、日志归档20ms

4.2 任务状态

任务在生命周期中经历以下状态转换 （定义于 task_scheduler.h:38-45）：

enum class TaskState {
    Pending,    // 已创建，等待依赖满足
    Ready,      // 依赖已满足，可被调度
    Running,    // 正在执行
    Suspended,  // 被更高优先级任务抢占
    Completed,  // 执行成功
    Failed,     // 执行失败
    Cancelled   // 被取消（含依赖取消传播）
};
设计决策 Suspended 状态独立于 Pending，因为被抢占的任务不需要重新检查依赖关系， 恢复时直接进入 Ready 队列头部，减少调度延迟约 40%。

10. 常见问题
高优先级任务持续涌入，低优先级任务会饿死吗？
不会。MLFQ 的时间片轮转保证每个优先级层在 500ms 内至少执行一次。 如果高优先级层持续满载，低优先级层的时间片会缩短但不会归零。 具体参数见 task_scheduler.cpp:85-92。
如何处理循环依赖？
DependencyGraph 在 addDependency() 时执行拓扑排序检测。 发现环时返回 DependencyError::CycleDetected，拒绝添加该边， 已有的合法边不受影响。
