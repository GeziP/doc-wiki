1. 概述

TaskScheduler 是基于多级反馈队列（MLFQ）的抢占式任务调度器，支持优先级调度、任务依赖和取消传播，解决生产环境中低优先级任务饥饿问题。

详细说明

1.1 背景

系统需要协调多个异步任务的执行顺序，确保高优先级任务优先调度，同时避免低优先级任务饥饿。 在生产环境中观察到，简单的优先级队列会导致低优先级清理任务长期得不到执行，最终引发内存泄漏 （test_task_scheduler.cpp:200-250 中有复现测试）。

1.2 解决方案

采用多级反馈队列（MLFQ）算法，将任务分为 4 个优先级层，每层独立管理。 调度器从最高优先级层开始扫描，空层跳过。层内使用时间片轮转，防止饥饿。

设计决策 选择 MLFQ 而非简单的优先级队列，因为生产环境中观察到低优先级清理任务 长期得不到执行，导致内存泄漏。MLFQ 的时间片机制保证每层在 500ms 内至少被调度一次 （task_scheduler.cpp:45-60）。

深入分析

MLFQ 算法细节

MLFQ 的核心思想是：新任务进入最高优先级队列，如果任务在时间片内未完成，则降级到下一级队列。 每隔 500ms，调度器执行"提升"操作，将所有任务重新放入最高优先级队列，防止饥饿。

2. 架构

分层架构：TaskManager（入口）→ TaskScheduler（调度核心）→ PriorityQueue（4 层队列）→ DependencyGraph（依赖解析）→ ThreadPool（执行）。

架构详解
层级职责核心模块关键接口
入口层任务创建/销毁TaskManagersubmit(), cancel()
调度层优先级调度 + 依赖解析TaskSchedulerschedule(), promote()
存储层4 层优先级队列PriorityQueueenqueue(), dequeue()
依赖层DAG 依赖图DependencyGraphaddDep(), ready()
执行层线程池执行ThreadPoolexecute()

2.1 跨模块调用链

任务提交的完整调用链：

TaskManager::submit(task)          // 入口
  → TaskScheduler::schedule(task)    // 调度
    → DependencyGraph::addDep(task)  // 注册依赖
    → PriorityQueue::enqueue(task)   // 入队
      → task.state = QUEUED          // 状态变更
  → ThreadPool::execute(task)        // 执行（异步）
设计决策 DependencyGraph 和 PriorityQueue 分离，因为依赖解析是 O(V+E) 的 DAG 遍历， 而队列操作是 O(log N)。合并会导致每次入队都触发依赖检查，性能差 10 倍 （test_task_scheduler.cpp:300-320 有基准测试）。

3. 任务状态机

任务生命周期包含 6 个状态：CREATED → QUEUED → RUNNING → COMPLETED/FAILED/CANCELLED，支持取消传播。

状态转换
当前状态事件目标状态动作
CREATEDsubmit()QUEUED入优先级队列
QUEUEDschedule()RUNNING分配线程
RUNNING完成COMPLETED触发依赖任务
RUNNING异常FAILED通知 TaskManager
QUEUED/RUNNINGcancel()CANCELLED传播取消到依赖
QUEUED超时CANCELLED自动清理
设计决策 取消传播采用 BFS 遍历依赖图，而非递归 DFS。因为深度依赖链可能导致栈溢出 （task_scheduler.cpp:200-220）。
Sources: task_state.h:1-60 task_scheduler.cpp:180-250
状态详细行为

QUEUED 状态

任务在 QUEUED 状态等待调度。调度器每 50ms 扫描一次队列，从最高优先级层开始。 如果任务在队列中等待超过 500ms，会被"提升"到更高优先级层（task_scheduler.cpp:60-80）。

RUNNING 状态

任务在 ThreadPool 中执行。执行期间，任务持有线程的独占访问权。 如果任务执行超过配置的超时时间，ThreadPool 会强制终止线程并触发 FAILED 状态转换。

4.2 使用示例

submit() — 提交任务

创建任务并提交到调度器。任务会自动进入最高优先级队列：

auto task = std::make_shared<Task>([]() {
    std::cout << "Hello from task" << std::endl;
});
auto id = scheduler.submit(task);  // 返回 TaskId
std::cout << "Task submitted: " << id << std::endl;

cancel() — 取消任务

取消任务会级联取消所有依赖该任务的后续任务：

bool cancelled = scheduler.cancel(taskId);
if (cancelled) {
    // 任务已取消，依赖它的任务也会被取消
    std::cout << "Task and dependents cancelled" << std::endl;
}

setPriority() — 动态调整优先级

运行中任务也可以调整优先级，下次调度周期生效：

scheduler.setPriority(taskId, Priority::CRITICAL);
// 下次调度周期（50ms 内）任务会提升到最高优先级
设计决策 submit() 返回 TaskId 而非 Task 对象，因为 Task 可能被移动到其他线程执行， 持有引用会导致生命周期问题。TaskId 是安全的句柄 （task_scheduler.h:55-58）。

5. 常见问题（FAQ）

基于源码逻辑推断的 5 个常见问题，覆盖任务饥饿、取消传播、并发安全等场景。

常见问题
Q1: 低优先级任务会永远得不到执行吗？

不会。MLFQ 的"提升"机制每 500ms 将所有任务重新放入最高优先级队列 （task_scheduler.cpp:60-80）。 因此低优先级任务最多等待 500ms 就会被调度。

Q2: 取消一个任务会影响其他任务吗？

会。cancel() 使用 BFS 遍历依赖图，级联取消所有依赖该任务的后续任务 （task_scheduler.cpp:200-220）。 如果只想取消单个任务，需要先调用 getDependencyGraph() 解除依赖关系。

Q3: 多线程同时 submit() 安全吗？

安全。PriorityQueue 使用 std::mutex 保护所有操作 （priority_queue.h:50-55）。 但高频并发提交可能导致锁竞争，建议批量提交。

Q4: 任务执行超时会怎样？

ThreadPool 会强制终止线程（通过 pthread_cancel），并将任务状态设为 FAILED （task_scheduler.cpp:250-260）。 超时时间可在配置中设置，默认 30s。

Q5: 如何调试任务调度顺序？

启用 SCHEDULER_DEBUG=1 环境变量，调度器会将每次调度决策写入日志 （task_scheduler.cpp:280-300）。 日志格式：[SCHED] task_id=X priority=Y queue_level=Z。
